# 选择

> 2026-05-13 | 由技术选型引申出的思考

## 起点

今天学定时器时说了一句"存在就有意义，选择是智慧"。setInterval 和 setTimeout 各有适用场景，没有绝对的优劣，关键是**你的回调是什么样的**。

这句话不仅适用于技术。选择这件事本身值得深入想清楚。

## 选择的本质是什么

选择不是"挑一个最好的"。选择是**在约束条件下，找到与目标最匹配的路径**。

三个要素：

```
目标（你想要什么）
  +
约束（你有什么条件）
  +
代价（你愿意放弃什么）
  ＝ 选择
```

很多人做选择时痛苦，不是因为选项不好，而是：
- 不清楚自己要什么（目标模糊）
- 不清楚自己能承受什么（代价模糊）
- 两个都想要（忽略约束）

## 为什么选择难

### 1. 信息永远不完整

你不可能在掌握所有信息后才做决定。技术选型如此，人生选择也如此。

- 你不可能试过所有框架再选一个
- 你不可能体验过所有职业再选一个
- 你不可能预见所有后果再做决定

所以选择本身包含**不确定性**，这是正常的，不是你的问题。

### 2. 沉没成本陷阱

已经投入的时间、精力、感情，会让人不舍得放弃。

```
"我已经学了三个月 Vue，现在换 React 好亏"
"我已经在这个项目上花了一年，不能放弃"
"我已经在这家公司干了三年..."
```

但过去投入的成本是**收不回来的**。选择应该基于**未来**的收益，不是过去的投入。

### 3. 害怕选错

"万一选错了怎么办？"

但回到今天学定时器的体会——**选择是可以动态调整的**。用 setInterval 发现不合适，可以换成递归 setTimeout。选了一条路发现不对，可以换。

选择不是一锤子买卖。大部分选择是**可逆的**，真正不可逆的选择其实很少。

## 做好选择的几个原则

### 原则一：先排除，再确认

和发现潜能的逻辑一样——排除比确认更快。

- 不需要找到"最好的"，先排除"明显不合适的"
- 剩下的选项差距不大时，选哪个都不会太差
- **纠结太久本身就是一种损失**（时间成本）

### 原则二：看场景，不看标签

setInterval 不是"差的"，setTimeout 不是"好的"——要看回调本身的特征。

人也是一样：
- 没有绝对好的选择，只有**适合当前场景**的选择
- 别人选的路，放到你的条件下未必好
- 同一个人，在不同阶段的最优选择也不同

### 原则三：选择之后，投入决定结果

选了 setInterval 还是 setTimeout，只是起点。能不能用好、是否在过程中调整，才是决定结果的关键。

```
好的选择 + 糟糕的执行 = 糟糕的结果
一般的选择 + 全力投入 = 不差的结果
```

大部分人高估了选择本身的重要性，低估了执行的力量。

### 原则四：允许自己试错

今天学到的实验法——"重点不是会不会，而是过程中的感受"。

- 快速试错比长期纠结效率高
- 试错的成本通常比想象的低
- 不试，永远不知道

## 选择与放弃

选择一个，就是放弃其他。这才是选择的真正代价。

但放弃不是失去，是**聚焦**。

```
什么都想要 → 什么都要不到
放弃一部分 → 聚焦剩下的 → 把它做到极致
```

回到昨天的感悟：框架要把一件事做到极致。人也一样。

选择的核心不是"得到最好的"，而是**确定你愿意为之付出代价的那一个**。

## 执行比选择更重要：一个真实的反思

选择前端职业 → 没问题。选择通过 Claude 每日学习 → 也没问题。选豆包、选 DeepSeek 都没问题。

**问题不在选择，在执行。** 选了前端但没有持续精进，选了学习工具但关键是怎么学。

今天的学习过程就是高执行力的例子——没有停留在"setInterval 和 setTimeout 是定时器"这个表面信息上，而是不断追问：它们有什么区别？setInterval 存在的意义？微任务宏任务的优先级？网络请求的 Promise.then 到底经历了什么？

**这个过程比选哪个 AI 工具重要得多。**

所以执行力的核心不是"每天坚持"，而是**你用什么方式对待你正在做的事**：

| | 低质量执行 | 高质量执行 |
|---|---|---|
| 学习 | 收藏、看懂、过了 | 追问、实验、用自己的话总结 |
| 前端 | 用框架完成任务 | 理解框架为什么这样设计 |
| 工作 | 交付需求 | 交付需求 + 想清楚为什么这么做 |

选了前端这件事没有错。问题不是"该不该选前端"，而是"在前端上的执行方式对不对"。

选择只是起点，执行才决定终点。

## AI 时代，精进前端的意义

AI 能讲清楚 setTimeout 的机制、微任务宏任务的优先级、事件循环，几秒就能完成。纯作为"信息"来学，意义在降低。

但今天真正获得的不是信息，是**判断力**。

```
没有理解的人：
  遇到问题 → 描述给 AI → AI 给方案 → 照做 → 下次类似问题重复

有理解的人：
  遇到问题 → 瞬间判断方向 → 用 AI 执行细节 → 验证
```

区别在于**你是 AI 的使用者，还是 AI 的依赖者。**

### 不是所有技术点都值得深挖

精进前端不等于把每个 API 的原理都学一遍。值得深挖的是**反复出现的思维模型**：

| 值得深挖 | 不值得深挖 |
|---|---|
| 事件循环、异步模型 | 某个 API 的参数细节 |
| 组件设计模式 | 框架版本迁移的步骤 |
| 状态管理的本质 | 配置文件的写法 |
| 渲染性能原理 | CSS 的某个特殊属性值 |

思维模型是**跨框架、跨时代的**。框架会变，AI 会更强，但"理解系统运转方式"的能力不会贬值。

### 所以意义是什么

不是"掌握前端知识"，而是**训练出能驾驭 AI 的思维方式**。知识点只是载体，真正的产出是脑子里的那张网。

这和之前的发现吻合——享受的是"从碎片中构建出整体，理解系统运转方式"。这不是在学前端，是在用前端训练自己。

## 费曼总结

选择是在目标、约束、代价之间找平衡。不存在完美的选择，只有适合当前场景的选择。信息永远不完整，所以快速试错比反复纠结更有效。选择之后，执行力比选择本身更重要——问题往往不在选择错了，而在执行方式不对。选择一个就意味着放弃其他，放弃不是失去，是聚焦。

存在就有意义，选择是智慧，执行决定一切。
